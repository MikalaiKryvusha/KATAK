## Вектор цели

**Achieve:** пользователь сохраняет весь расчёт турбины одним файлом `.md` на языке страницы и загружает такой файл обратно.
Файл несёт две части: блоки JSON, которые читает парсер страницы, и текст для человека — пояснительную записку к
расчёту и текст к чертежу.

## Критерии приёмки `[AI]` (черновик, уточняется при планировании)

1. Кнопка «Экспорт в MD» сохраняет файл `katak-<D>mm.md`; весь текст файла на языке страницы (RU или EN).
2. Каждый блок ```` ```json ```` файла разбирается `JSON.parse` без ошибки; ключи JSON не зависят от языка страницы.
3. Импорт файла восстанавливает все поля формы: экспорт → импорт → экспорт даёт файл, байт в байт равный первому.
4. Файл, сохранённый на русском, загружается на английской странице, и наоборот: язык текста не мешает парсеру.
5. Пояснительная записка содержит исходные данные, результаты расчёта с единицами и источники формул (`researches/`).
6. Текст к чертежу содержит размеры каждой детали (ротор, обтекатель) и технические требования к печати (материал,
   сопло, слой, стенка).

## Решение к реализации `[AI]` (набросок)

1. Структура файла: заголовок; блок ```` ```json katak-input ```` (все поля формы, версия формата); блок
   ```` ```json katak-result ```` (результаты расчёта, только для чтения); раздел «Пояснительная записка»; раздел «Чертёж».
2. Парсер импорта читает только блок `katak-input` и проверяет версию формата; результаты страница считает заново.
3. Проверка: `tools/ui-run.mjs` — экспорт, разбор JSON, импорт, повторный экспорт, сравнение двух файлов; то же на EN.

PENDING: состав раздела «Чертёж» — текстовая спецификация размеров (так понял агент) или ещё и рисунки SVG внутри MD; при
планировании идеи принести владельцу вопрос со сценариями.
